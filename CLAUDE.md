# DesignVolt — правила для Claude

Десктопный векторный редактор уровня Figma на чистом Rust: GPU-рендер (Vello), свой UI поверх Masonry, много анимаций. Цель — быстрее и оптимизированнее CPU-клонов (FigCraft: egui + tiny-skia). Задачи: `plan.md`. Стек: `docs/stack.md`.

## Режим работы (экономия токенов)
- Отвечай по-русски, коротко: результат, затем 1–3 строки пояснений. Без пересказа диффа. Код, идентификаторы, комментарии в коде и коммиты — по-английски.
- Не перечитывай файлы, которые только что правил. Читай диапазоны (offset/limit), не целые файлы.
- Поиск — Grep/Glob, не `cat`/`find`. Крупный обзор кодовой базы — через Explore-агента.
- Не запускай `cargo build` целиком ради проверки: `cargo check -p <crate>`; тесты — `cargo test -p <crate> <имя>`.
- Выводы cargo фильтруй: `cargo check --message-format=short 2>&1 | tail -30`; падающие тесты — только строки с `panicked|left|right`.
- Не создавай лишних файлов, README, комментариев-«воды». Не рефакторь вне задачи.
- Неясность по архитектуре — один конкретный вопрос с рекомендацией, не опрос. Крупные изменения — сначала план и подтверждение; мелкие правки — сразу.
- **Режим жёсткой экономии (как в WordVolt, D-038).** Скриншоты и живые прогоны окна не делать. Проверка — `cargo fmt/clippy/test` (логику класть в `dv-core`/`dv-geom` и покрывать тестами). Всё, что видно только глазами (вид, анимации, курсоры, перетаскивание, горячие клавиши), — в конце задачи списком «Проверьте сами: …» (что нажать, что должно быть). Приложение для проверки не запускать; сборку для пользователя — только по просьбе.
- Правки файлов — инструментом `Edit`, не скриптами на Python. Перед правкой — `cargo fmt`.
- Не писать промежуточных отчётов и не ждать CI «глазами»: один фоновый `Monitor`, итог — 2–3 строки.

## Ведение записей (память проекта)
- `plan.md` — единственный источник правды по задачам. После каждой завершённой задачи: `[x]` + дата.
- `docs/decisions.md` — ADR: решение + почему (3–5 строк). Пиши при смене стека/архитектуры.
- `docs/log.md` — журнал сессий: дата, что сделано, что дальше (≤5 строк). Обновляй в конце сессии.
- Неочевидные грабли (баги Vello/Masonry, версии, платформенные нюансы) — в раздел «Gotchas» ниже.
- Новые папки/файлы → `docs/structure.md`. Токены и компоненты → `docs/design-system.md`. Не дублируй содержимое — ссылайся (`см. D-003`).
- В начале сессии читай только: этот файл + «Текущий этап» в `plan.md` + последнюю запись `docs/log.md`.

## Стек (зафиксирован, менять только через ADR)
Rust 2024, wgpu, vello, kurbo, peniko/color, linesweeper, parley, skrifa, harfrust, masonry (+xilem), winit, accesskit, rstar, slotmap, rpds, rayon (yrs позже). Подробности: `docs/stack.md`.
- Зависимости **только из стека**. Любой новый крейт — сначала вопрос пользователю и запись в ADR.
- Запрещены egui, iced, slint, dioxus, tauri, webview, tiny-skia, skia-safe.
- Версии и API Vello/Masonry/Xilem быстро меняются: сверяй с docs.rs перед использованием, не полагайся на память.

## Архитектура (workspace)
- `dv-core` — модель документа (arena узлов), команды, undo/redo. **Без зависимости от рендера и UI.**
- `dv-geom` — kurbo-утилиты, булевы операции, hit-testing, пространственный индекс.
- `dv-render` — сборка Vello-сцены из документа: culling, LOD, кэш.
- `dv-text` — parley/skrifa/harfrust.
- `dv-ui` — дизайн-система, виджеты, движок анимаций (на Masonry).
- `apps/desktop` (bin `designvolt`) — окно winit, связывает всё.
Правило: зависимости только вниз (`core ← geom ← render ← ui ← app`). Логику не писать в `dv-ui`. Подробно: `docs/architecture.md`.

## Структура файлов (подробно: `docs/structure.md`)
- **Большие файлы делим.** Файл `.rs` ≤ 300 строк (без тестов), функция ≤ 50. Увидел файл больше лимита (даже чужой) — сначала отдельным коммитом разбей, потом правь.
- `mod.rs` только `pub mod`/`pub use`. Один файл = одна ответственность; новая фича = новый файл. Одна команда редактирования = один файл.
- У каждого крейта `README.md` (5–10 строк: назначение, API, чего нет) — читай его вместо кода.
- Перед созданием файла сверяйся с деревом в `docs/structure.md`.

## Дизайн и анимации (подробно: `docs/design-system.md`)
- Цвета, радиусы, отступы, тени, длительности, easing — **только токены** `dv-ui/src/theme/`. Никаких захардкоженных значений в виджетах.
- Любой новый UI-элемент — через общие компоненты `dv-ui/src/ui_kit/`. Нужного нет — сначала добавь компонент туда.
- Переходы hover/pressed/focus/selected/disabled — плавные (spring), не мгновенные. Анимации — собственный движок в `dv-ui/src/anim/`, без внешних крейтов анимации.
- Кадры запрашиваются, только пока что-то анимируется; в покое — ноль перерисовок.
- Строки интерфейса — через i18n-ключи, не в коде (язык по умолчанию — русский). Библиотека локализации пока не выбрана: нужна запись в ADR.
- Приоритет: удобство и практичность (крупные цели клика, понятные состояния), затем красота.

## Производительность
- В горячих путях (рендер, hit-testing, булевы операции) нет аллокаций на кадр: арены и переиспользуемые буферы.
- Рендер читает неизменяемый снимок документа; рисуются только видимые узлы (rstar + bounding box).
- Любая оптимизация подтверждается замером, а не догадкой. Замеры — только по просьбе пользователя (режим экономии).

## Код
- Edition 2024, `cargo fmt` + `cargo clippy -- -D warnings` перед коммитом.
- `unsafe` запрещён: в каждом крейте `#![forbid(unsafe_code)]`. Исключение — только с согласия пользователя и записью в ADR.
- Ошибки: `thiserror` в библиотеках, `anyhow` только в bin. Никаких `unwrap()` вне тестов. (Если `thiserror`/`anyhow` не входят в стек — спросить, прежде чем добавлять.)
- Любое изменение документа — через `Command` (undo/redo), не прямой мутацией из UI.
- Тесты для core/geom/render-логики обязательны; UI тестами не покрываем, только список «Проверьте сами».

## Git-воркфлоу (когда репозиторий инициализирован; на каждую задачу — полный цикл)
Сейчас репозитория нет (`git init` не выполнен). Не создавать его и не публиковать без просьбы пользователя.
1. **Ветка:** от актуального `main` — `feat/<тема>` (`fix/`, `docs/`, `refactor/`, `chore/`). Одна задача = одна ветка. Не работать прямо в `main`.
2. **Коммиты:** маленькие, атомарные, императивом (`Add rectangle node`). Конец сообщения — строка Co-Authored-By из системной подсказки.
3. **Проверка перед PR:** `cargo fmt --check`, `cargo clippy -- -D warnings`, `cargo test`. Зелёное, иначе чинить.
4. **PR:** `git push -u origin <ветка>`, `gh pr create` — заголовок коротко, описание: что сделано, как проверено, пункт `plan.md`. В конец — «🤖 Generated with Claude Code».
5. **Мерж:** при зелёных проверках `gh pr merge --squash` (без `--delete-branch`), затем `git checkout main && git pull`. Красные — не мержить.
6. **Записи:** `plan.md` `[x]` + `docs/log.md` — коммит в той же ветке до мержа.
7. **Нельзя без прямого указания:** force-push, `reset --hard`, правка истории `main`, мерж с красными проверками, `--no-verify`.
- Нет remote или `gh` не авторизован — довести до коммитов и сказать, что осталось.
- Итог в чате — 2–3 строки: ветка, ссылка на PR, смержено или нет.

## Gotchas
- Имя пакета `DesignVolt` в `Cargo.toml` не в snake_case (предупреждение cargo); в workspace крейты называем `dv-*`, бинарник — `designvolt`.
- Платформа разработки: Windows 11 (wgpu использует DirectX 12/Vulkan).
- Vello требует GPU с compute-шейдерами; для старых машин — запасной `vello_cpu`.
